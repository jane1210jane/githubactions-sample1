# Stage 2 演習課題 解答

[stage-02-triggers-and-pr-gate.md](../stage-02-triggers-and-pr-gate.md) の演習課題3問への解答です。
先に自分で予想してから読んでください。

## 問1: `docs/` だけを変更した PR を作り、CI が走ることを確認する。なぜ `pull_request` 側には `paths-ignore` を付けていないのか

**予想**: `ci.yml` の `push:` 側には `paths-ignore: ["docs/**", "**/*.md"]` が付いているので、
同じように `pull_request:` 側にも付けて、ドキュメントだけの PR では CI をスキップした方が
速くて合理的に思えるかもしれません。

**実際に確かめる**: `docs/` 配下のファイルだけを変更した PR を作ると、`pull_request` トリガーで
`Lint & Test` が普通に起動し、成功します（実際に本タスクの docs PR で確認済みです）。

**解答**: `Lint & Test` は ruleset の**必須チェック**に指定されています。もし `pull_request:` 側にも
`paths-ignore` を付けると、ドキュメントだけの PR では `ci.yml` そのものが起動しなくなります。
このとき GitHub は、必須チェックの結果を「成功」とはみなしません。**「未報告
（Expected — Waiting for status to be reported）」のまま**になり、報告が来ないので
いつまで経ってもマージ可能になりません。つまり、フィルタで実行を減らしたつもりが、
ドキュメントだけの PR を**永久にマージできなくする**という逆効果になります。
`push:` 側は必須チェックの対象ではない（`main` に直接 push すること自体が ruleset で
禁止されている）ため、こちらだけフィルタを付けても同じ問題は起きません。

## 問2: `concurrency` の `group` から `${{ github.ref }}` を消すと何が起きるか

**予想**: `group` を `${{ github.workflow }}` だけにしても、キャンセルされる実行が
少し増えるだけで、大きな問題にはならなそうに思うかもしれません。

**実際に確かめる**: `concurrency.group` を `${{ github.workflow }}` のみに変更すると、
`group` の値は常に `CI` という同じ文字列になります。つまり、ブランチや PR に関係なく
**リポジトリ内のすべての CI 実行が同じグループに属します**。

**解答**: `cancel-in-progress: ${{ github.event_name == 'pull_request' }}` と組み合わせると、
どこかの PR で新しい push が起きるたびに、**別の PR で進行中の実行までキャンセルされます**。
自分のブランチで push した覚えがないのに、他人（あるいは自分の別の PR）の push によって
自分の PR の CI が `cancelled` になる、という混乱を招きます。`group` に
`${{ github.ref }}`（ブランチまたは PR の ref）を含めることで、「同じブランチ・同じ PR の
中でだけ古い実行を打ち消す」という、本来意図した範囲に限定できます。**`group` には
必ずブランチ（や PR）を識別する値を含めること**が重要です。

## 問3: `ci.yml` のジョブの `name:` を `Lint and Test` に変更して PR を出す

**解答**: ruleset の必須チェックには `Lint & Test` という文字列で登録してあります。
ジョブの `name:` を `Lint and Test` に変更すると、CI ワークフロー自体は問題なく実行され、
成功もしますが、GitHub に報告されるチェック名が `Lint and Test` に変わります。
その結果、ruleset が待っている `Lint & Test` という名前のチェックは
**二度と報告されなくなり**、PR の必須チェックはずっと「未報告」のままになります。
つまり CI は緑で成功しているにもかかわらず、**PR はマージできなくなります**。

必須チェックはジョブの `name:` という**文字列**に紐づいており、`jobs:` の
キー名（この場合は `test`）とは無関係です。`name:` は人間が読みやすくするための
ラベルに見えますが、実際には ruleset との**識別子**でもあるため、安易に変更してはいけません。
このリポジトリでは、この演習は実際にジョブの `name:` を変更する実験を行うと、
その場でこのリポジトリの必須チェックが機能しなくなり後続の作業に支障が出るため、
**実際の変更・実際の PR 作成は行わず**、上記のとおり知識として確認するにとどめています。
手元で試す場合は、確認後に必ず `name: Lint & Test` へ戻してください。
