# フェーズ3（Stage 6–8）実装計画

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** CI を「速く壊れにくい」段階から「安全に外へ出せる」段階へ進め、Stage 6（セキュリティ基礎）、Stage 7（ETL 化とコンテナ）、Stage 8（AWS へ実デプロイ）を教材として完成させる。

**Architecture:** Stage 6 で伏線（`permissions` / `env:` 経由 / SHA ピン留め）を回収し、`zizmor` をワークフロー専用のセキュリティ検査として常設する。Stage 7 で CLI を ETL へ発展させ、コンテナ化して GHCR へ push し、`actions/cache` を自作する。Stage 8 で OIDC による一時認証を使って ECR へ push し、Lambda（コンテナイメージ）へ staging → production の順にデプロイする。ジョブ間のファイル受け渡し（Stage 0 で予告した artifact の回収）はここで行う。

**Tech Stack:** GitHub Actions / uv / Docker / GHCR / AWS（OIDC・ECR・Lambda・S3）/ boto3 / moto / zizmor / actionlint

## Global Constraints

- 依存管理は `uv` のみ。`uv.lock` は必ずコミットする。`pip install` を直接使う手順は書かない。
- 金額は `Decimal`。`float` を使わない。データ構造は `frozen=True` dataclass と `tuple`。
- すべてのワークフローに `permissions:` をトップレベルで書く。**Stage 6 以降はコメントを「Stage 6 で回収する」から実際の理由の説明に差し替える**（伏線の回収）。
- `run:` の中に `${{ }}` を直接書かない。外部から来る値は `env:` を経由させる。**Stage 6 でこの理由を説明する。**
- **Stage 6 以降、サードパーティ action は SHA でピン留めし、行末に `# vX.Y.Z` のコメントを付ける。** `actions/*` も同様に扱う。
- **ruleset の必須チェック名 `Lint & Test` を変更しない。** 変更すると全 PR がマージ不能になる。
- 解説ドキュメントは8節フォーマット（ゴール / 前提 / なぜ必要か / 手順 / 何が変わったか / つまずきポイント / 演習課題 / 実務への持ち込みメモ）。
- **転記ブロックには出所宣言 `<!-- transcript: <path> @ <tag> -->` を付ける**（Task 1 で導入）。行番号引用は転記ブロック内を指し、本文で**どのファイルの**行番号かを必ず名指しする。
- 演習の解答は `docs/stages/answers/stage-NN.md` に別置きする。
- **計画に書かれた GitHub Actions・AWS の仕様に関する断定は、転記してよい文ではなく実装時に検証すべき主張として扱う。** 実測と食い違ったら実測を採用し、その旨を報告する（設計書 §10「計画由来の事実誤認への備え」）。
- Windows 固有の注意は README の「Windows で進める場合」節を参照させ、各解説で繰り返さない。
- ドキュメント本文は日本語。コード識別子とファイル名は英語。
- **`main` への直接 push は ruleset により拒否される。** すべてブランチ → PR → `Lint & Test` 緑 → squash マージ。`--admin` は使わない。
- 各ステージ完了時に `git tag stage-NN` を打ち push する。**既存の `stage-00`〜`stage-05` は移動しない。**
- `gh pr create` は `--json` 非対応。作成後に `gh pr view --json number -q .number` で番号を取る。`gh pr create` 直後の `gh pr checks --watch` は未登録で即終了するので、`gh run list --limit 1` で実行開始を確認してから待つ。
- ローカルに Docker・AWS CLI・Terraform は無い。Docker を使う検証はすべて CI（`ubuntu-latest`）で行う。AWS 側の一度きりの準備は**学習者が手動で実施**する（Task 2）。

```python
DECLARATION = re.compile(r"^<!--\s*transcript:\s*(\S+)\s*@\s*(\S+)\s*-->\s*$")
TRANSCRIPT_BODY = re.compile(r"^\s*\d+\|\s?")
```

- `SourceReader` 型エイリアスと `Transcript` を追加する。

```python
SourceReader = Callable[[str, str], tuple[str, ...] | None]


@dataclass(frozen=True)
class Transcript:
    """解説に転記されたファイル1つ分のブロック。"""

    source_path: str
    tag: str
    declared_at: int
    line_numbers: frozenset[int]
    body: tuple[str, ...]

    @property
    def name(self) -> str:
        """本文が名指しに使うファイル名（basename）。"""
        return self.source_path.rsplit("/", 1)[-1]
```

- `Citation` に `file_hint: str | None` を加える。既存の3フィールドの後ろに置く。
- `collect_transcripts(lines)` を実装する。`_classify` でフェンスの内外を判定しながら、フェンス開始行の直前の非空行が `DECLARATION` に一致すればその宣言を採用する。ブロック内の各行から `TRANSCRIPT_LINE` で番号を、`TRANSCRIPT_BODY` を除去して本文を取り出す。番号付き行が1行も無いフェンスは転記ブロックではないので無視する。
- `collect_citations(lines, names)` に、宣言されたファイル名の集合 `names` を渡す。各本文行を走査し、**同じ行の中で引用より前に現れた最後のファイル名**を `file_hint` にする。同じ行に無ければ、文書内でそれまでに現れた最後のファイル名を引き継ぐ。1つも無ければ `None`。
- `check_document(path, read_source)` を次の順で検査する。
  1. 閉じ忘れフェンス（既存の検査を維持）
  2. 番号付きフェンスなのに宣言が無い → `「転記ブロックに出所宣言（<!-- transcript: <path> @ <tag> -->）がありません」`
  3. 各 `Transcript` について `read_source(source_path, tag)` を呼ぶ。`None` なら `「<path> @ <tag> の内容を取得できません」`。取得できたら本文と行単位で比較し、最初に食い違った位置を `「<path> の転記が <tag> 時点の内容と一致しません（<N>行目）」`。行数が違う場合も同じ形式で報告する
  4. 各 `Citation` について、`file_hint` が `None` なら `「<N>行目 がどのファイルの引用か本文から判別できません」`。`file_hint` に対応する `Transcript` が無ければ `「<name> の転記ブロックがありません」`。あれば、その `line_numbers` にすべて含まれるかを検査し、外れていれば `「<name> の <N>行目 は転記ブロックの範囲外」`
- `git_source_reader(repo_root)` を実装する。

```python
def git_source_reader(repo_root: Path) -> SourceReader:
    """`git show <tag>:<path>` で転記元の内容を読む SourceReader を返す。"""

    def read(source_path: str, tag: str) -> tuple[str, ...] | None:
        completed = subprocess.run(  # noqa: S603
            ["git", "show", f"{tag}:{source_path}"],
            cwd=repo_root,
            capture_output=True,
            text=True,
            encoding="utf-8",
        )
        if completed.returncode != 0:
            return None
        return tuple(completed.stdout.splitlines())

    return read
```

- `main` を `check_document(path, git_source_reader(Path.cwd()))` を呼ぶ形に変える。

`subprocess` と `Callable` の import を追加すること。`ruff` の `S` ルールは有効になっていないので `# noqa` は不要な場合がある。**`ruff check` が通る形にすること（不要な `noqa` はそれ自体が指摘対象になる）。**

     ```bash
     ACCOUNT_ID=$(aws sts get-caller-identity --query Account --output text)
     cat > trust-policy.json <<JSON

         "Effect": "Allow",

         "Action": "sts:AssumeRoleWithWebIdentity",
         "Condition": {
           "StringEquals": {
             "token.actions.githubusercontent.com:aud": "sts.amazonaws.com",
             "token.actions.githubusercontent.com:sub": "repo:jane1210jane/githubactions-sample1:ref:refs/heads/main"
           }
         }
       }]
     }
     JSON
     aws iam create-role --role-name github-actions-sales-report \
     ```

```python
"""CSV を読み、月次集計し、JSON として書き出す ETL。

CLI が「人が読む表を標準出力に出す」のに対し、ETL は「入力を読み、変換し、
出力先に書く」。コンテナに載せて無人で動かすには後者の形が要る。
集計そのものは aggregate モジュールに委ね、ここは入出力だけを担当する。
"""

from __future__ import annotations

import csv
import json
from collections.abc import Iterable
from dataclasses import dataclass
from decimal import Decimal
from pathlib import Path

from sales_report.aggregate import MonthlyTotal, aggregate_monthly, parse_records


@dataclass(frozen=True)
class EtlResult:
    """ETL 1回分の実行結果の要約。ログや戻り値に使う。"""

    month_count: int
    total_amount: Decimal


def to_json_payload(totals: Iterable[MonthlyTotal]) -> dict[str, object]:
    """集計結果を JSON にできる形へ変換する。

    金額は文字列にする。JSON の数値は倍精度浮動小数点なので、
    Decimal のまま数値として書くと精度が落ちる。
    """
    return {
        "months": [
            {
                "month": total.month,
                "total_amount": str(total.total_amount),
                "record_count": total.record_count,
            }
            for total in totals
        ]
    }


def run_etl(input_path: Path, output_path: Path) -> EtlResult:
    """input_path の CSV を集計し、output_path に JSON を書く。"""
    with input_path.open(newline="", encoding="utf-8") as stream:
        totals = aggregate_monthly(parse_records(csv.DictReader(stream)))

    output_path.parent.mkdir(parents=True, exist_ok=True)
    output_path.write_text(
        json.dumps(to_json_payload(totals), ensure_ascii=False, indent=2),
        encoding="utf-8",
    )

    return EtlResult(
        month_count=len(totals),
        total_amount=sum((total.total_amount for total in totals), Decimal("0")),
    )
```

```yaml
# 走らせたいタイミングも違うため。

      - "docs/**"
      - "**/*.md"

    branches: [main]
  workflow_dispatch:

  contents: read

    name: Build & Push
    runs-on: ubuntu-latest
    timeout-minutes: 20

      - name: リポジトリを取得する
        uses: actions/checkout@<SHA>  # <version>
        with:
          persist-credentials: false

      # buildx を使うと、レイヤキャッシュを外部に出し入れできるようになる。
      - name: Docker Buildx を用意する

        with:
          path: /tmp/.buildx-cache
          # Dockerfile と依存定義が変わればキャッシュを作り直す。
          key: buildx-${{ runner.os }}-${{ hashFiles('Dockerfile', 'uv.lock', 'pyproject.toml') }}
          # 完全一致が無ければ、同じ OS の直近のキャッシュから始める。

            buildx-${{ runner.os }}-

          password: ${{ secrets.GITHUB_TOKEN }}

        uses: docker/build-push-action@<SHA>  # <version>

          context: .

          # push しようとすると必ず失敗する。
          push: ${{ github.event_name != 'pull_request' }}
          tags: |
            ${{ env.IMAGE_NAME }}:${{ github.sha }}
            ${{ env.IMAGE_NAME }}:latest
          cache-from: type=local,src=/tmp/.buildx-cache
          cache-to: type=local,dest=/tmp/.buildx-cache-new,mode=max

      # 新しいものと入れ替える。
```

```python
from pathlib import Path
from typing import Any

import boto3

from sales_report.etl import run_etl

REQUIRED_SECTIONS = ("input", "output")


def handler(event: dict[str, Any], context: object) -> dict[str, Any]:
    """S3 のオブジェクトを ETL にかけ、結果を S3 に書き戻す。"""
    source, destination = _read_locations(event)
    client = boto3.client("s3")

    with tempfile.TemporaryDirectory() as workspace:
        input_path = Path(workspace) / "input.csv"
        output_path = Path(workspace) / "output.json"

        client.download_file(source["bucket"], source["key"], str(input_path))
        result = run_etl(input_path, output_path)
        client.upload_file(str(output_path), destination["bucket"], destination["key"])

    return {
        "month_count": result.month_count,
        "total_amount": str(result.total_amount),
        "output": destination,
    }


def _read_locations(event: dict[str, Any]) -> tuple[dict[str, str], dict[str, str]]:
    missing = [section for section in REQUIRED_SECTIONS if section not in event]
    if missing:
        raise ValueError(f"イベントに必要な項目がありません: {', '.join(missing)}")
    return event["input"], event["output"]
```

```yaml
# Stage 8: 実際に AWS へデプロイする。
# 長期のアクセスキーは置かない。OIDC でその実行専用の一時認証を取る。
name: Deploy

on:
  push:
    branches: [main]
    paths-ignore:
      - "docs/**"
      - "**/*.md"
  workflow_dispatch:
    inputs:
      rollback_to_version:
        description: ロールバック先の Lambda バージョン番号（空ならロールバックしない）
        required: false
        default: ""
        type: string

concurrency:
  # デプロイは重ねない。走行中のものを消さずに待たせる。
  group: deploy-${{ github.ref }}
  cancel-in-progress: false

permissions:
  contents: read

jobs:
  build:
    name: Build & Push to ECR
    runs-on: ubuntu-latest
    timeout-minutes: 20
    permissions:
      contents: read
      # OIDC のトークンを発行してもらうために必要。これが無いと
      # aws-actions/configure-aws-credentials は認証できない。
      id-token: write
    outputs:
      image-uri: ${{ steps.push.outputs.image-uri }}
    steps:
      - name: リポジトリを取得する
        uses: actions/checkout@<SHA>  # <version>
        with:
          persist-credentials: false

      # 長期のアクセスキーは使わない。この実行のためだけの一時認証を取る。
      - name: AWS の一時認証を取得する
        uses: aws-actions/configure-aws-credentials@<SHA>  # <version>
        with:
          role-to-assume: ${{ secrets.AWS_ROLE_ARN }}
          aws-region: ${{ vars.AWS_REGION }}

      - name: ECR にログインする
        id: ecr
        uses: aws-actions/amazon-ecr-login@<SHA>  # <version>

      - name: イメージをビルドして push する
        id: push
        env:
          REGISTRY: ${{ steps.ecr.outputs.registry }}
          REPOSITORY: ${{ vars.ECR_REPOSITORY }}
          IMAGE_TAG: ${{ github.sha }}
        run: |
          uri="${REGISTRY}/${REPOSITORY}:${IMAGE_TAG}"
          docker build --tag "${uri}" .
          docker push "${uri}"
          echo "image-uri=${uri}" >> "${GITHUB_OUTPUT}"

      # Stage 0 で予告した「ジョブ間でファイルを渡す仕組み」がここで要る。
      # 値が1つなら outputs で足りるが、デプロイの記録は増えていくものなので
      # 最初からファイルの形にしておく。
      - name: デプロイ用のマニフェストを書き出す
        env:
          IMAGE_URI: ${{ steps.push.outputs.image-uri }}
          COMMIT_SHA: ${{ github.sha }}
        run: |
          cat > deployment-manifest.json <<JSON
          {
            "image_uri": "${IMAGE_URI}",
            "commit_sha": "${COMMIT_SHA}",
            "built_at": "$(date --iso-8601=seconds)"
          }
          JSON
          cat deployment-manifest.json

      - name: マニフェストを artifact として保存する
        uses: actions/upload-artifact@<SHA>  # <version>
        with:
          name: deployment-manifest
          path: deployment-manifest.json
          retention-days: 7

  deploy-staging:
    name: Deploy to staging
    runs-on: ubuntu-latest
    needs: build
    timeout-minutes: 15
    environment: staging
    permissions:
      contents: read
      id-token: write
    steps:
      - name: マニフェストを取得する
        uses: actions/download-artifact@<SHA>  # <version>
        with:
          name: deployment-manifest

      - name: AWS の一時認証を取得する
        uses: aws-actions/configure-aws-credentials@<SHA>  # <version>
        with:
          role-to-assume: ${{ secrets.AWS_ROLE_ARN }}
          aws-region: ${{ vars.AWS_REGION }}

      - name: Lambda を更新して staging エイリアスを張り替える
        env:
          FUNCTION_NAME: ${{ vars.LAMBDA_FUNCTION_NAME }}
        run: |
          image_uri=$(python -c "import json;print(json.load(open('deployment-manifest.json'))['image_uri'])")
          echo "デプロイするイメージ: ${image_uri}"
          aws lambda update-function-code \
            --function-name "${FUNCTION_NAME}" \
            --image-uri "${image_uri}" >/dev/null
          aws lambda wait function-updated --function-name "${FUNCTION_NAME}"
          version=$(aws lambda publish-version --function-name "${FUNCTION_NAME}" --query Version --output text)
          echo "公開したバージョン: ${version}"
          aws lambda update-alias --function-name "${FUNCTION_NAME}" \
            --name staging --function-version "${version}" \
            || aws lambda create-alias --function-name "${FUNCTION_NAME}" \
                 --name staging --function-version "${version}"
          {
            echo "## staging へデプロイしました"
            echo ""
            echo "- イメージ: \`${image_uri}\`"
            echo "- Lambda バージョン: ${version}"
          } >> "${GITHUB_STEP_SUMMARY}"

  deploy-production:
    name: Deploy to production
    runs-on: ubuntu-latest
    needs: deploy-staging
    timeout-minutes: 15
    # この environment には承認者が設定してある。ここでワークフローが止まり、
    # 人が承認するまで先へ進まない。
    environment: production
    permissions:
      contents: read
      id-token: write
    steps:
      - name: AWS の一時認証を取得する
        uses: aws-actions/configure-aws-credentials@<SHA>  # <version>
        with:
          role-to-assume: ${{ secrets.AWS_ROLE_ARN }}
          aws-region: ${{ vars.AWS_REGION }}

      - name: production エイリアスを張り替える
        env:
          FUNCTION_NAME: ${{ vars.LAMBDA_FUNCTION_NAME }}
          ROLLBACK_TO: ${{ inputs.rollback_to_version }}
        run: |
          if [ -n "${ROLLBACK_TO}" ]; then
            target="${ROLLBACK_TO}"
            echo "ロールバック先として指定されたバージョン: ${target}"
          else
            target=$(aws lambda get-alias --function-name "${FUNCTION_NAME}" \
              --name staging --query FunctionVersion --output text)
            echo "staging と同じバージョンを production へ: ${target}"
          fi
          aws lambda update-alias --function-name "${FUNCTION_NAME}" \
            --name production --function-version "${target}" \
            || aws lambda create-alias --function-name "${FUNCTION_NAME}" \
                 --name production --function-version "${target}"
          {
            echo "## production を更新しました"
            echo ""
            echo "- Lambda バージョン: ${target}"
          } >> "${GITHUB_STEP_SUMMARY}"
```

**注意**: `build` ジョブの `docker build` は、Lambda 関数がまだ存在しない場合の `update-function-code` で失敗する。**関数が存在しないときにどうするかは、Task 2 の手順書で「関数は学習者が作る」としているか、「ワークフローが作る」としているかで決まる。** 手順書の内容と矛盾しないようにし、矛盾していたらどちらかを直して報告すること。
