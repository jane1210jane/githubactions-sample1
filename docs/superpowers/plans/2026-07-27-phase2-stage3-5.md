# フェーズ2（Stage 3–5）実装計画

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** CI を「動く」から「速く・壊れにくく・再利用できる」段階へ引き上げ、Stage 3（高速化と再現性）、Stage 4（品質ゲート）、Stage 5（再利用と構造化）を教材として完成させる。

**Architecture:** 単一ジョブだった `ci.yml` を、静的検査ジョブ・matrix テストジョブ・集約ゲートジョブの3層に再構成する。**必須チェック名 `Lint & Test` は集約ジョブが引き継ぐ**ため、リポジトリの ruleset は最後まで一度も変更しない。Stage 5 で検査とテストを reusable workflow へ切り出し、`ci.yml` は呼び出し側の薄い殻になる。加えて、フェーズ1で3回再発した「解説の行番号引用のズレ」を機械検査するツールを導入する。

**Tech Stack:** GitHub Actions / uv / pytest / pytest-cov / ruff / mypy / actionlint（公式 Docker イメージ）

## Global Constraints

- 依存管理は `uv` のみ。`uv.lock` は必ずコミットする。`pip install` を直接使う手順は書かない。
- 金額は `Decimal`。`float` を使わない。データ構造は `frozen=True` dataclass と `tuple`。
- すべてのワークフローに `permissions: contents: read` をトップレベルで書き、`# 最小権限にしておく。なぜ必要かは Stage 6 で回収する。` というコメントを添える。**理由の解説は Stage 6 まで行わない。**
- `run:` の中に `${{ }}` を直接書かない。外部から来る値は `env:` を経由させる。理由の解説は Stage 6。
- アクションはメジャーバージョンタグで参照する（例 `actions/checkout@v7`）。SHA ピン留めは Stage 6。
- **`astral-sh/setup-uv` の浮動メジャータグは `v7` までしか存在しない**（最新リリースは `v9.0.0`）。`@v7` を使う。この事実は `docs/stages/stage-01-python-ci.md` に記載済み。
- **ruleset の必須チェック名 `Lint & Test` を変更しない。** 変更すると全 PR がマージ不能になる。ジョブ構成を変えるときは、この名前を持つジョブが必ず1つ存在するようにする。
- 解説ドキュメントは8節フォーマット（ゴール / 前提 / なぜ必要か / 手順 / 何が変わったか / つまずきポイント / 演習課題 / 実務への持ち込みメモ）。
- **解説内の行番号引用は、その解説に転記したワークフロー YAML のブロック内を指す。** 実ファイルを直接指さない。転記ブロックは行頭が `NN| ` 形式（半角数字 + 半角パイプ + 半角スペース）のフェンス付きコードブロックとし、それが `stage-NN` タグ時点の内容であることを明記する。既存3解説がこの形式なので、それに合わせる。
- 演習の解答は `docs/stages/answers/stage-NN.md` に別置きする。
- ドキュメント本文は日本語。コード識別子とファイル名は英語。
- **Windows 固有の注意は README の「Windows で進める場合」節に集約**し、各解説からはそこを参照する。ステージごとに同じ注意書きを繰り返さない。
- **`main` への直接 push は ruleset により拒否される。** すべての変更はブランチ → PR → `Lint & Test` 緑 → squash マージ。`--admin` は使わない。
- 各ステージ完了時に `git tag stage-NN` を打ち、push する。**既存の `stage-00` / `stage-01` / `stage-02` は移動しない。**
- `gh run watch` / `gh pr checks` は引数なしだとハングする。必ず明示的な id を渡す。
- **`gh pr create` の直後に `gh pr checks --watch` を打つと `no checks reported` を返して即座に終わる。**
  チェックがまだ登録されていないためで、失敗ではない。`gh run list --limit 1` で実行の開始を
  確認してから `gh pr checks <番号> --watch` を打つこと。`gh pr create` は `--json` を受け付けないので、
  PR 番号は作成後に `gh pr view --json number -q .number` で取る。

- [ ] **Step 5: ツールを実装する**

`tools/check_doc_citations.py`:

```python
"""解説ドキュメント内の「N行目」引用を、同じ文書に転記された YAML と突き合わせて検査する。

本教材では、各ステージの解説にそのステージ時点のワークフロー YAML を転記し、
本文の行番号引用は転記ブロック内の行を指す約束にしている。
転記ブロックを編集したときに引用がズレるのを人の目で防ぐのは繰り返し失敗したため、
機械で検査する。

転記ブロックは、行頭が `NN| ` 形式の行だけで構成されたフェンス付きコードブロック。
"""

from __future__ import annotations

import re
import sys
from collections.abc import Iterable, Sequence
from dataclasses import dataclass
from pathlib import Path

FENCE_PREFIX = "```"
TRANSCRIPT_LINE = re.compile(r"^\s*(\d+)\|")
CITATION = re.compile(r"(\d+)\s*(?:〜|～|-)\s*(\d+)\s*行目|(\d+)\s*行目")
EXIT_OK = 0
EXIT_PROBLEMS_FOUND = 1


@dataclass(frozen=True)
class Citation:
    """本文中の行番号引用。単一行の引用は start == end とする。"""

    source_line: int
    start: int
    end: int


@dataclass(frozen=True)
class Problem:
    path: Path
    source_line: int
    message: str


def collect_transcript_line_numbers(lines: Sequence[str]) -> frozenset[int]:
    """転記ブロックに現れる行番号をすべて集める。"""
    numbers: set[int] = set()
    for line in _transcript_lines(lines):
        match = TRANSCRIPT_LINE.match(line)
        if match:
            numbers.add(int(match.group(1)))
    return frozenset(numbers)


def collect_citations(lines: Sequence[str]) -> tuple[Citation, ...]:
    """転記ブロックの外にある行番号引用を集める。"""
    citations: list[Citation] = []
    for source_line, line in _prose_lines(lines):
        for match in CITATION.finditer(line):
            if match.group(3) is not None:
                value = int(match.group(3))
                citations.append(Citation(source_line=source_line, start=value, end=value))
            else:
                citations.append(
                    Citation(
                        source_line=source_line,
                        start=int(match.group(1)),
                        end=int(match.group(2)),
                    )
                )
    return tuple(citations)


def check_document(path: Path) -> tuple[Problem, ...]:
    lines = path.read_text(encoding="utf-8").splitlines()
    transcript = collect_transcript_line_numbers(lines)
    problems: list[Problem] = []

    for citation in collect_citations(lines):
        label = _label(citation)
        if not transcript:
            problems.append(
                Problem(path, citation.source_line, f"{label} を引用しているが転記ブロックが無い")
            )
            continue
        if citation.start > citation.end:
            problems.append(Problem(path, citation.source_line, f"{label} は範囲が逆順"))
            continue
        missing = [n for n in range(citation.start, citation.end + 1) if n not in transcript]
        if missing:
            problems.append(
                Problem(path, citation.source_line, f"{label} は転記ブロックの範囲外")
            )

    return tuple(problems)


def main(argv: Sequence[str] | None = None) -> int:
    paths = tuple(_iter_markdown(Path(argument) for argument in (argv or ["docs/stages"])))
    problems = tuple(problem for path in paths for problem in check_document(path))

    for problem in problems:
        print(f"{problem.path}:{problem.source_line}: {problem.message}", file=sys.stderr)

    if problems:
        print(f"{len(problems)} 件の引用ズレが見つかりました", file=sys.stderr)
        return EXIT_PROBLEMS_FOUND

    print(f"{len(paths)} 件のドキュメントを検査し、引用ズレはありませんでした")
    return EXIT_OK


def _transcript_lines(lines: Sequence[str]) -> list[str]:
    return [line for line, is_prose in _classify(lines) if not is_prose]


def _prose_lines(lines: Sequence[str]) -> list[tuple[int, str]]:
    return [
        (number, line)
        for number, (line, is_prose) in enumerate(_classify(lines), start=1)
        if is_prose
    ]


def _classify(lines: Sequence[str]) -> list[tuple[str, bool]]:
    """各行を (本文か否か) の判定つきで返す。フェンス行自体は本文扱いしない。"""
    classified: list[tuple[str, bool]] = []
    inside_fence = False
    for line in lines:
        if line.lstrip().startswith(FENCE_PREFIX):
            inside_fence = not inside_fence
            classified.append((line, False))
            continue
        classified.append((line, not inside_fence))
    return classified


def _iter_markdown(paths: Iterable[Path]) -> list[Path]:
    found: list[Path] = []
    for path in paths:
        if path.is_dir():
            found.extend(sorted(path.rglob("*.md")))
        else:
            found.append(path)
    return found


def _label(citation: Citation) -> str:
    if citation.start == citation.end:
        return f"{citation.start}行目"
    return f"{citation.start}〜{citation.end}行目"


if __name__ == "__main__":
    raise SystemExit(main())
```

```yaml
# Stage 1 でアプリに CI を追加し、Stage 2 でトリガーを設計し直し、
# Stage 3 でジョブを「静的検査」「テスト」「集約ゲート」の3層に分けた。
# ruleset の必須チェック名 `Lint & Test` は集約ジョブ gate が引き継ぐ。
name: CI

on:
  # PR には必ず CI を走らせる。paths で絞らないのは、
  # 必須チェックにしたときにドキュメントだけの PR が永久に待ち状態になるため。
  pull_request:
    branches: [main]
  # main への push は、ドキュメントだけの変更なら省略してよい。
  push:
    branches: [main]
    paths-ignore:
      - "docs/**"
      - "**/*.md"

# 同じブランチで新しい実行が始まったら、古い実行を止める。
# main では途中で止めたくないので、PR のときだけキャンセルする。
concurrency:
  group: ${{ github.workflow }}-${{ github.ref }}
  cancel-in-progress: ${{ github.event_name == 'pull_request' }}

# permissions: このワークフローが GITHUB_TOKEN に許す操作。
# 最小権限にしておく。なぜ必要かは Stage 6 で回収する。
permissions:
  contents: read

env:
  # actionlint はバージョンを固定して使う。docker タグの :latest は
  # いつ中身が変わるか分からないため、教材としても避ける。
  ACTIONLINT_VERSION: "1.7.7"

jobs:
  static:
    name: Static Checks
    runs-on: ubuntu-latest
    # ハングしたジョブが課金され続けるのを防ぐ。既定は 360 分と長い。
    timeout-minutes: 10
    steps:
      - name: リポジトリを取得する
        uses: actions/checkout@v7

      - name: uv と Python をセットアップする
        uses: astral-sh/setup-uv@v7
        with:
          python-version: "3.12"

      - name: 依存関係をインストールする
        run: uv sync --locked

      - name: フォーマットを確認する
        run: uv run ruff format --check .

      - name: lint を確認する
        run: uv run ruff check .

      - name: 解説の行番号引用を検証する
        run: uv run python tools/check_doc_citations.py docs/stages

      # ワークフロー自体も検査対象にする。式の綴り間違いや存在しない
      # コンテキスト参照は、実行してみるまで気づけないことが多い。
      - name: ワークフローを actionlint で検査する
        run: |
          docker run --rm \
            --volume "${PWD}:/repo" \
            --workdir /repo \
            "rhysd/actionlint:${ACTIONLINT_VERSION}" -color

  test:
    name: Test
    runs-on: ubuntu-latest
    timeout-minutes: 10
    steps:
      - name: リポジトリを取得する
        uses: actions/checkout@v7

      - name: uv と Python をセットアップする
        uses: astral-sh/setup-uv@v7
        with:
          python-version: "3.12"

      - name: 依存関係をインストールする
        run: uv sync --locked

      - name: テストを実行する
        run: uv run pytest -v

  # 集約ゲート。ruleset が必須チェックとして見ているのはこのジョブの name。
  # 依存ジョブの構成を変えても、この名前さえ保てば ruleset を触らずに済む。
  gate:
    name: Lint & Test
    runs-on: ubuntu-latest
    needs: [static, test]
    # 依存ジョブが失敗しても gate 自身は動かす必要がある。
    # if を書かないと、依存が1つでも失敗した時点で gate は skipped になり、
    # 必須チェックが「未報告」のまま PR が永久に待ち状態になる。
    if: always()
    timeout-minutes: 5
    steps:
      - name: 依存ジョブの結果を判定する
        env:
          DEPENDENCY_RESULTS: ${{ join(needs.*.result, ' ') }}
        run: |
          echo "依存ジョブの結果: ${DEPENDENCY_RESULTS}"
          for result in ${DEPENDENCY_RESULTS}; do
            if [ "${result}" != "success" ]; then
              echo "success ではない依存ジョブがあります"
              exit 1
            fi
          done
          echo "すべての依存ジョブが success です"
```

`docs/stages/answers/stage-03.md` に3問と解答を書く。

- **問1**: `fail-fast` を既定（`true`）に戻し、`windows-latest` のテストだけをわざと失敗させて挙動を比べる。
  解答: `true` だと他の matrix ジョブが即座にキャンセルされ、「Windows だけの問題なのか全環境の問題なのか」が判別できない。原因調査のための情報がキャンセルによって失われる。CI の目的が「壊れたことを知る」ではなく「何が壊れたかを知る」ことである以上、調査中は `false` が有利。実行時間を優先する場面（マージキューなど）では `true` が有利になる
- **問2**: `gate` ジョブの `name:` を `CI Gate` に変えると何が起きるか予想し、**実行はせずに**説明する。

- **問3**: matrix に `python-version: "3.11"` を追加すると何が起きるか。実際に追加して確かめる。

- [ ] **Step 1: reusable workflow を作る**

`.github/workflows/reusable-python-ci.yml`:

```yaml
# 再利用可能ワークフロー。
# workflow_call で呼ばれることだけを想定しており、単体では起動しない。
# 他リポジトリからは `uses: <owner>/<repo>/.github/workflows/reusable-python-ci.yml@<ref>`
# として呼べる。
name: Reusable Python CI

on:
  workflow_call:
    inputs:
      python-versions:
        description: テストする Python バージョンの JSON 配列
        required: false
        default: '["3.12", "3.13"]'
        type: string

permissions:
  contents: read

env:
  ACTIONLINT_VERSION: "1.7.7"

jobs:
  static:
    name: Static Checks
    runs-on: ubuntu-latest
    timeout-minutes: 10
    steps:
      - name: リポジトリを取得する
        uses: actions/checkout@v7

      - name: Python 環境をセットアップする
        uses: ./.github/actions/setup-python-env
        with:
          python-version: "3.12"

      - name: フォーマットを確認する
        run: uv run ruff format --check .

      - name: lint を確認する
        run: uv run ruff check .

      - name: 型を確認する
        run: uv run mypy src tools

      - name: 解説の行番号引用を検証する
        run: uv run python tools/check_doc_citations.py docs/stages

      - name: ワークフローを actionlint で検査する
        run: |
          docker run --rm \
            --volume "${PWD}:/repo" \
            --workdir /repo \
            "rhysd/actionlint:${ACTIONLINT_VERSION}" -color

  test:
    name: Test (${{ matrix.os }} / Python ${{ matrix.python-version }})
    runs-on: ${{ matrix.os }}
    timeout-minutes: 10
    strategy:
      fail-fast: false
      matrix:
        os: [ubuntu-latest, windows-latest]
        # 入力は文字列なので、fromJSON で配列に戻してから matrix に渡す。
        python-version: ${{ fromJSON(inputs.python-versions) }}
        exclude:
          - os: windows-latest
            python-version: "3.12"
    steps:
      - name: リポジトリを取得する
        uses: actions/checkout@v7

      - name: Python 環境をセットアップする
        uses: ./.github/actions/setup-python-env
        with:
          python-version: ${{ matrix.python-version }}

      - name: テストを実行する
        run: uv run pytest -v --cov-report=html

      - name: カバレッジ HTML を artifact として保存する
        if: always()
        uses: actions/upload-artifact@v4
        with:
          name: coverage-html-${{ matrix.os }}-${{ matrix.python-version }}
          path: htmlcov/
          retention-days: 7
```

- [ ] **Step 2: `ci.yml` を呼び出し側に書き換える**

`.github/workflows/ci.yml` を以下で**全面的に置き換える**。

```yaml
# Stage 1 で CI を追加し、Stage 2 でトリガーを設計し、Stage 3 でジョブを3層に分け、
# Stage 4 で品質ゲートを入れ、Stage 5 で検査とテストを再利用可能ワークフローへ切り出した。
# このファイルに残っているのは「いつ動かすか」と「何を必須とするか」だけ。
name: CI

on:
  pull_request:
    branches: [main]
  push:
    branches: [main]
    paths-ignore:
      - "docs/**"
      - "**/*.md"

concurrency:
  group: ${{ github.workflow }}-${{ github.ref }}
  cancel-in-progress: ${{ github.event_name == 'pull_request' }}

# permissions: このワークフローが GITHUB_TOKEN に許す操作。
# 最小権限にしておく。なぜ必要かは Stage 6 で回収する。
permissions:
  contents: read

jobs:
  meta:
    name: Metadata
    runs-on: ubuntu-latest
    timeout-minutes: 5
    outputs:
      version: ${{ steps.read.outputs.version }}
    steps:
      - name: リポジトリを取得する
        uses: actions/checkout@v7

      - name: pyproject.toml からバージョンを読む
        id: read
        run: |
          version=$(grep -m1 '^version = ' pyproject.toml | cut -d '"' -f 2)
          echo "読み取ったバージョン: ${version}"
          echo "version=${version}" >> "${GITHUB_OUTPUT}"

  # 再利用可能ワークフローの呼び出し。同じリポジトリ内なので ./ で参照できる。
  # jobs.<id>.uses を使うジョブには steps を書けない。呼び出しそのものがジョブになる。
  checks:
    name: Checks
    uses: ./.github/workflows/reusable-python-ci.yml

  # 集約ゲート。ruleset が必須チェックとして見ているのはこのジョブの name。
  # 呼び出し先のジョブ名は `Checks / Static Checks` のように変わるが、
  # この名前さえ保てば ruleset を触らずに済む。
  gate:
    name: Lint & Test
    runs-on: ubuntu-latest
    needs: [meta, checks]
    if: always()
    timeout-minutes: 5
    steps:
      - name: 結果をステップサマリに書く
        env:
          APP_VERSION: ${{ needs.meta.outputs.version }}
          CHECKS_RESULT: ${{ needs.checks.result }}
        run: |
          {
            echo "## CI 結果"
            echo ""
            echo "| 項目 | 値 |"
            echo "| --- | --- |"
            echo "| バージョン | ${APP_VERSION} |"
            echo "| 検査とテスト | ${CHECKS_RESULT} |"
          } >> "${GITHUB_STEP_SUMMARY}"

      - name: PR 向けの案内を出す
        if: github.event_name == 'pull_request'
        run: |
          {
            echo ""
            echo "カバレッジの詳細は Artifacts の \`coverage-html-*\` を開いてください。"
          } >> "${GITHUB_STEP_SUMMARY}"

      - name: 依存ジョブの結果を判定する
        env:
          DEPENDENCY_RESULTS: ${{ join(needs.*.result, ' ') }}
        run: |
          echo "依存ジョブの結果: ${DEPENDENCY_RESULTS}"
          for result in ${DEPENDENCY_RESULTS}; do
            if [ "${result}" != "success" ]; then
              echo "success ではない依存ジョブがあります"
              exit 1
            fi
          done
          echo "すべての依存ジョブが success です"
```

- [ ] **Step 2: Stage 5 の解説を書く**

`docs/stages/stage-05-reuse.md` を8節フォーマットで作成する。各節に必ず含める内容:

1. **ゴール** — 重複したステップを composite action にまとめ、CI 本体を reusable workflow として他リポジトリへ配れる形にする
2. **前提** — `stage-04` 完了時点
3. **なぜ必要か** — Stage 3 でジョブを分け Stage 4 でジョブが増えた結果、「checkout → setup-uv → uv sync」が3箇所に重複した。片方だけ直す事故が起きる。また会社では同じ CI を複数リポジトリに配りたくなるが、コピーで配ると二度と揃わない
4. **手順** — Task 9 Step 2〜5、Task 10 Step 1〜6
5. **何が変わったか** — 3つの転記ブロックを置き、それぞれの行番号を指しながら説明する
   - **composite action と reusable workflow の違い** — composite action は**ステップの塊**で、ジョブの中に埋め込まれる。reusable workflow は**ジョブの塊**で、それ自体がジョブになる。runner を指定できるのは後者だけ
   - composite action の `runs.using: composite` と、`run:` に `shell:` が必須であること
   - composite action に checkout を含めなかった理由
   - `jobs.<id>.uses` を使うジョブには `steps` を書けないこと
   - `workflow_call` の `inputs` と `fromJSON()` — matrix に配列を渡すには文字列で受けて変換する
   - **呼び出すと Checks 名が `Checks / Static Checks` のように変わること**（Task 10 Step 4 の実測）。だからこそ `gate` を呼び出し側に残し、必須チェック名を保っている
   - 他リポジトリから呼ぶときの書式 `uses: <owner>/<repo>/.github/workflows/<file>@<ref>`
6. **つまずきポイント**
   - composite action の `run:` に `shell:` を書き忘れると `Required property is missing: shell` で落ちる
   - `uses: ./...` はローカルパス参照。**呼び出し元で checkout していないと action が見つからない**
   - reusable workflow を呼ぶと Checks 名が変わる。**必須チェックにしている名前が呼び出し先にあると、ゲートが外れる**
   - reusable workflow は呼び出し元の `env:` を引き継がない。必要な値は `inputs` で渡す
   - `workflow_call` の `inputs` に配列型は無い。JSON 文字列で渡して `fromJSON()` する
   - 他リポジトリの reusable workflow を `@main` で参照すると、向こうの変更が予告なく自分の CI を壊す。タグかコミットで固定する
7. **演習課題** — 下記 Step 3 の3問
8. **実務への持ち込みメモ** — 共通 CI を配るときは、まず1リポジトリで使い込んでから切り出す。使う前に抽象化すると、必要な入力が分からないまま設計してしまう。切り出し先はタグで参照し、更新は意図的に行う
